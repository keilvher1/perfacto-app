포항 지역 맛집/카페/관광지/숙박 정보를 제공하는 지도 기반 앱입니다.
Google Maps에 장소 마커를 표시하고, 카테고리 필터링, 장소 저장, 리뷰
작성 등의 기능을 제공합니다.

이전 버그 수정 사항: PlaceModel.id 타입 불일치(int → String) 및 Flutter
Web 커스텀 마커 아이콘 렌더링 문제를 해결하여 이제 18개 마커가
정상적으로 표시됩니다.

1. 해결된 문제

1.1 마커 하나만 표시되는 문제 (해결완료)

- 원인 1 - ID 타입 불일치: Firestore 문서 ID는 문자열인데
  PlaceModel.id가 int타입이었음. 모든 ID가 0으로 파싱되어
  MarkerId(“0”)이 중복, Set<Marker>에서 1개만 생존.

- 원인 2 - 커스텀 마커 아이콘:
  ui.PictureRecorder/Canvas/picture.toImage() 방식이 Flutter Web에서
  투명 이미지 생성. BitmapDescriptor.defaultMarkerWithHue()로 펴백 적용.

- 원인 3 - 레이스 컨디션: 아이콘 로딩과 장소 데이터 로딩 비동기 경쟉
  조건으로 아이콘 미로드 시 마커 추가 실패. 펴백 처리 및 아이콘 로드 후
  마커 업데이트 로직 추가.

2. Critical 이슈 (즉시 수정 필요)

2.1 이중 인증 시스템 혼재

FirebaseAuthService와 레거시 AuthService(Backend API)가 공존합니다.
LoginPage는 authNotifierProvider(Riverpod)를 사용하지만 MyPage는
FirebaseAuthService.isLoggedIn을 직접 체크합니다. 로그인 상태 불일치가
발생할 수 있습니다.

- 권장: 하나의 인증 시스템(Firebase)으로 통일하고 레거시 AuthService를
  제거하세요.

2.2 검색 기능 미구현

홈 화면 상단의 검색바(“어디로 떠나볼까요?”)는 UI만 존재하고 실제 검색
로직이 없습니다. TextField에 onChanged 핸들러가 없어 입력해도 아무
반응이 없습니다.

- 권장: Firestore 장소 데이터 검색 기능을 구현하세요 (장소명, 주소,
  카테고리 기반).

2.3 리뷰 시스템 불완전

바텀시트의 리뷰 탭이 항상 비어있습니다. _loadReviews() 함수가 빈
리스트를 반환합니다. 또한 3단계 리뷰 작성 UI에 이미지 업로드와 텍스트
코멘트 필드가 없습니다 (ReviewModel에는 필드 존재).

- 권장: 리뷰 로드 로직을 Firestore에서 실제로 가져오도록 구현하고,
  이미지/코멘트 입력 UI를 추가하세요.

2.4 저장 장소 데이터 유실 위험

저장된 장소가 SharedPreferences(로컬 저장소)에만 저장됩니다. 앱
삭제/재설치 시 모든 저장 데이터가 사라집니다. 코드 주석에도 “임시
해결책”으로 명시되어 있습니다.

- 권장: Firestore users/{uid}/savedPlaces 컬렉션으로 클라우드 동기화를
  구현하세요.

2.5 HOT/POINT 탭 미구현

하단 네비게이션의 HOT과 POINT 탭이 플레이스홀더 상태입니다. 아이콘과
“준비 중입니다” 텍스트만 표시됩니다. 사용자가 매번 탭하면 빈 페이지를
보게 됩니다.

- 권장: 기능을 구현하거나, 출시 전까지 탭을 숨기세요.

3. Major 이슈 (조속한 수정 필요)

3.1 에러 처리 부족

대부분의 에러가 제네릭 Exception으로 처리됩니다. 사용자에게 원시 에러
메시지(“Exception: ...”)가 노출되며, 네트워크 실패 시 재시도 메커니즘이
없습니다.

3.2 로딩 상태 표시 부재

비동기 작업 시 스켈레톤 로더나 프로그레스 인디케이터가 없습니다. 지도
로딩, 장소 데이터 로딩, 프로필 이미지 업로드 등 모두 무반응 상태가
발생합니다.

3.3 거리 표시 오류

바텀시트의 장소 거리가 항상 “0km”로 표시됩니다. 위치 기반 거리 계산
로직이 실패 시 조용히 0으로 펴백됩니다.

3.4 인증 가드 부재

비로그인 상태에서 보호된 페이지(저장, 리뷰 작성 등)에 접근 가능합니다.
버튼 클릭 시에만 LoginPage로 리다이렉트되지만, 글로벌 라우트 가드가
없습니다.

3.5 Apple 로그인 Android 미지원

Apple 로그인 버튼이 Android에서도 표시되지만 실제로는 작동하지 않습니다.
플랫폼 감지 후 조건부 표시가 필요합니다.

3.6 메모리 누수 위험

MapController, AnimationController, 리스너 등이 일부 페이지에서 dispose
처리되지 않습니다. 장시간 사용 시 메모리 문제가 발생할 수 있습니다.

4. Moderate 이슈 (개선 필요)

4.1 바텀시트 UX

- 탭(Home/Reviews/Photos)이 70% 이상 확장해야만 보임 → 사용자가 발견하기
  어려움

- 저장 버튼이 로그인 필요한지 사전 안내 없음

- 주소 확장 버튼 클릭 시 중복 라벨 표시

4.2 상태 관리 비일관성

setState, Riverpod(FutureProvider, StateNotifier), 일반 Service 클래스가
혼재되어 있습니다. 통일된 상태 관리 패턴이 필요합니다.

4.3 비밀번호 찾기 미구현

로그인 페이지의 “비밀번호 찾기” 링크가 TODO 상태입니다. 코드에 “준비
중입니다” 메시지만 존재합니다.

4.4 Firestore 검색 제한

친구 검색이 대소문자 구분(접두사 기반)으로 작동합니다. “홍길동”을
검색해도 “홍길동맛집”이 나오지만 “길동”으로는 검색 불가합니다.

4.5 Google Maps Marker Deprecated 경고

콘솔에 google.maps.Marker deprecated 경고가 표시됩니다.
AdvancedMarkerElement로 마이그레이션이 필요합니다.

4.6 접근성 문제

Flutter Web Canvas 렌더링으로 인해 접근성 트리에서 버튼/라벨을 인식할 수
없습니다. 스크린 리더 지원이 불가합니다.

4.7 성능 문제

모든 장소 데이터를 한 번에 로드합니다(페이지네이션 없음). RankingPage는
전체 데이터를 클라이언트에서 정렬합니다. 이미지 lazy loading이 없습니다.

5. Minor 이슈 (개선 권장)

- 디버깅 코드: 전체 코드베이스에 print() 문이 많이 남아있습니다.
  프로덕션에서는 제거해야 합니다.

- 매직 스트링: 카테고리 코드(“restaurant”, “cafe” 등)가 하드코딩되어
  있습니다. 상수로 관리하세요.

- 죽은 코드: review_write_page.dart가 사용되지
  않습니다(review_write_new_page.dart가 활성). 제거하세요.

- 언어 혼재: 에러 메시지가 한국어/영어 혼재됩니다. 일관성 있게
  통일하세요.

- 오프라인 모드: 네트워크 단절 감지나 오프라인 모드가 없습니다.

6. 긍정적 평가

- 지도 기반 UI가 직관적이고 카테고리 필터 칩이 잘 배치되어 있습니다.

- 마커가 18개 정상 표시되며 카테고리별 다른 색상으로 구분됩니다.

- 3단계 리뷰 시스템(신호등 → 이유 선택 → 비교)이 창의적입니다.

- 드래그 가능한 바텀시트가 3단계 스냅으로 잘 구현되어 있습니다.

- 포항 지역 구/군 폴리곤 오버레이가 시각적으로 훌륭합니다.

- Firebase + Riverpod 아키텍처가 적절하며 확장 가능성이 좋습니다.

- Google/Apple 소셜 로그인이 지원됩니다.

7. 우선순위 로드맵

Phase 1: 긴급 수정 (1-2주)

- 검색 기능 구현 (Firestore 장소명/주소 검색)

- 리뷰 로드 로직 연결 (_loadReviews → Firestore)

- 이중 인증 시스템 통합 (Firebase로 통일)

- 거리 계산 버그 수정

Phase 2: 핵심 기능 완성 (2-4주)

- 저장 장소 Firestore 클라우드 동기화

- HOT 탭 구현 (인기 장소/트렌드)

- POINT 탭 구현 (포인트/리워드 시스템)

- 리뷰 이미지 업로드 및 코멘트 필드 추가

- 에러 처리 및 로딩 상태 개선

Phase 3: 폴리시 (4-6주)

- Google Maps AdvancedMarkerElement 마이그레이션

- 접근성 개선 (Semantics 위젯 추가)

- 성능 최적화 (페이지네이션, 이미지 lazy loading)

- 코드 클린업 (print 제거, 죽은 코드 제거, 매직 스트링 상수화)

- 오프라인 모드 및 네트워크 재시도 로직
